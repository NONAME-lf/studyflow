# Формат гайда захисту

Богдан просив **коротко, без води**: попередні довгі версії відхилені, прийнятий формат — `reports/guide-stages-2-3.tex` (3 сторінки). Не довше.

## Правила

- Обсяг ≤ 3 сторінки A4, LaTeX, той самий `preamble.tex`.
- Шапка: загальний час (≈ 8 хв), позначення **Б** = Богдан, **А** = Артемій, що відкрити заздалегідь (PDF, демо, Swagger, Mailpit, Notion).
- Далі по слайдах/сторінках: `[Б] Слайд N — назва.` + **одна репліка 2–3 речення** курсивом у лапках: що це і чому так. Без таймінгів, без описів «що показувати», крім необхідних дій (напр. «перемкнутись на браузер»).
- Розподіл реплік за RACI: Богдан — архітектура, backend, БД, unit-тести, API, нагадування; Артемій — план спринта, демо UI, E2E/інтеграційні тести, рефлексія.
- Наприкінці «Якщо спитають» — 6–8 питань, відповідь в один рядок.
- Останній рядок — «Цифри напам'ять» (кількість тестів, coverage, ендпоінтів, SP план/факт).

## Ймовірні питання для етапу 4 (відповіді заповнити фактами)

- Чому модульний моноліт, а не мікросервіси? (2 розробники, один домен; мікросервіси — оверхед на інфраструктуру)
- Чому Prisma, а не TypeORM?
- Як зберігаються токени і чому refresh у httpOnly cookie?
- Як перевіряються ролі (староста/учасник)? Що, якщо обійти UI?
- Що мокається в модульних тестах, а що справжнє в інтеграційних?
- Як нагадування уникають дублікатів?
- Який coverage і чому не 100 %?
- Що не встигли і чому? (з рефлексії)
